## Resource and persistence

Add migration023; never edit001–022. A share's identity is the exact `(group_id, workspace_id, recipient_principal_id, semantic_version_id)` composite. Reference the immutable semantic version by its composite FK, not knowledge_id/current head. There is one current state per tuple: never-approved revision0 (absence), then positive monotonically increasing revision, active or revoked. Store approving human principal and exact verified issuer/subject binding, grant ID, timestamps. A genuinely new explicit approval may replace the issuer and increments revision; revocation is sticky until another explicit approval at the current revision. Historical approval replay never reactivates a revoked grant.

Use private share state, immutable operation receipts and content-free selected-read audit. No PUBLIC or runtime-role table privileges; narrow SECURITY DEFINER entrypoints with fixed search_path, revoked default PUBLIC execution and checked authorization. Protect receipts/audit from update/delete/truncate. Match established privileged migration owner/runtime roles. Never copy semantic content or mint a proposal/decision/promotion as a sharing side effect.

## Human transport and commands

POST `/api/memory-shares/approve`, `/api/memory-shares/revoke`, `/api/memory-shares/get`. Reuse the real core gateway: cryptographically verified human identity, exact configured Origin and Fetch Metadata, bounded streaming JSON, explicit namespace/workspace selectors, no-store responses, uniform safe errors. Machines and mixed identities fail before protected body work. `tenant:member` is admission only; the sharing service independently enforces all current target authority. It never grants existing memory:read.

Approve/revoke bodies have exactly `recipientId`, `memoryId`, `expectedRevision`, `operationKey`; IDs and operationKey are UUIDs, revision is a safe nonnegative integer. Reject unknown fields, invalid types and caller-supplied actor, permission, content, head or identity claims. Scope comes from the existing gateway selector, actor only from verified identity. Read body has exactly `memoryId` and optional boolean `history` default false. The authenticated principal is the recipient: there is no read-as-recipient parameter.

New approval requires a current human workspace grant administrator with legitimate memory read authority, active same-tenant human recipient, unlocked matching workspace and an existing independently approved immutable semantic version. Names/email are not identity or authority. A recipient is distinct from the approving actor. Revocation requires current legitimate workspace grant administration, not historical authorship; it must remain possible after the original issuer loses authority. No future-version, linked-evidence, neighbor, proposal, review, delete or admin rights are implied.

Scope idempotency by tenant/workspace/actor/operationKey; hash the full normalized operation, recipient, exact version and expected revision. Exact retry returns byte-identical historical receipt only after current caller authorization checks. A changed command under the key conflicts without writes. A stale expected revision conflicts without writes. Revoke of an absent share is privacy-safe not_found; repeat revoke under the same key replays, while a different-key no-op revoke conflicts. Receipts clearly describe operation-time effect, not current grant state; never append mutable status to an immutable receipt. They contain identifiers/revision/action/time only, no memory content. Receipts are returned to the authorized command actor, never exposed by selected-read.

## Exact disclosure contract

Successful read returns exactly `{memory: {id, content, created_at}}` with the approved immutable content/time. No knowledge_id, version number, mutable head/lifecycle, decision/proposal/evidence IDs, audit, grant roster, related items, counts, ranking or cursor. Do not use memory_projection or SELECT * as the response source. Missing, foreign, unshared and revoked targets have identical not_found response status/body after successful caller admission. Tenant authentication failure remains the existing authentication/admission denial.

With history=false, return that exact approved ID only while its head is current and lifecycle current. With history=true, return only that same approved ID, including a superseded/deprecated version; never resolve its successor or enumerate history. Sharing one version never shares another version. A default read becoming unavailable can reveal lifecycle change; this bounded API does not claim zero lifecycle inference or constant-time resistance. Existing memory_get semantics do not change.

Every read freshly validates the requesting recipient's actual human identity binding, active principal/membership, same tenant/workspace and lock state; the active exact share; and its approving human's original binding, active principal/membership and current grant-management/read authority. Issuer authority loss attenuates dependent reads, without fabricating a share-revocation receipt. An explicit share revocation remains terminal until explicit reapproval. Positive checks must not be cached.

## Transactions, ordering and trusted boundary

Use a dedicated multi-party transaction, not scopedTransaction's single-actor prelock. Learn candidate issuer IDs privately, then lock involved principals/memberships in deterministic principal order, relevant human bindings/tenant, workspace (shared for reads, exclusive for share mutations), current issuer/admin grant rows, exact share row, and head when current eligibility matters. Re-read and revalidate every discovered dependency after locking. Existing identity/access/client mutation order must be inspected for compatibility; no shared-to-exclusive workspace upgrade. Serialize absent-share creation by workspace/key locking and uniqueness. Use established finite query/lock/transaction timeouts; do not weaken or retry around permission controls.

Hold required authorization locks through read audit and commit. Prove read-first may finish before revoke, whereas revoke-first prevents disclosure; likewise issuer demotion/recipient identity loss. This is transaction ordering, not retroactive withdrawal of delivered bytes. If source inspection reveals an incompatible lock order, return the precise conflict before widening scope or relaxing checks.

Audit success and mutation/read must commit atomically; induced audit failure rolls the entire operation back and returns no content. Read audit is dedicated, content-free and not recipient-readable; existing workspace memory read-audit predicates stay strict. The SQL connection/settings are a trusted server assertion boundary, as documented in persistence.ts, not a public arbitrary-SQL API. JWT verification remains in the actual gateway; do not claim PostgreSQL independently verifies a JWT. Direct restricted-role tests must prove table/internal-helper denial and outer-helper authorization/scope checks, not merely exercise owner SQL.
