## Source, catalog and authority

Source request exact keys: sourceId UUID, endpointId UUID, profile baseline|project, roots1–8 distinct `{digest:lowercase SHA256,kind}`, ecosystems1–2 unique npm|pypi, catalogRevisionId UUID|null. Server derives group/workspace. Roots are fingerprints, never persisted raw paths. Population digest is SHA256 of canonical sourceId/endpointId/profile/sorted roots/sorted ecosystems; catalog identity is separately bound and cannot merge populations. Runner must use explicit authorized paths, prove their exact root fingerprints and profile classification, reject broad homes/symlinks/out-of-root traversal, and never infer default roots.

Only a current signed human with explicit workspace_admin grant and `workspace:grants:manage` may enroll/change/disable source or approve a catalog. This uses an existing scoped action, not org-admin inheritance or a live new grant. Recheck actor/current membership/grant/lock under transaction; immutable configuration event includes actor/rationale/validation/evidence IDs/result. A schema/parser function is not approval.10.1 performs no enrollment. A source revision is immutable; a separate locked head points to current revision/active state. Revocation or owner authority loss blocks new leases and ingestion.

External advisory feed allowlist is EMPTY by default. Initial catalogs are explicit internal-reviewed documents approved through the same signed-human boundary, not network polling or acceptance of arbitrary publisher claims. Catalog revision includes sourceId, publisher identifier, HTTPS source URL (no user-info/query/fragment), publishedAt, fetchedAt, canonical SHA256, verification rule `human-reviewed-sha256`, approval actor/receipt, classification `internal`, redaction `allowlist-v1`, retention `append-only`, expiry and entries. Maximum128 entries; each entry has opaque UUID, ecosystem npm|pypi, normalized ASCII package name, exact bounded version, severity low|medium|high|critical. No executable ranges/commands or free-form mitigation. Canonical JSON digest includes the full normalized metadata and sorted entry identities; immutable approval binds exact digest. Source URL/publisher remain provenance, not a fetched-data claim. Verified/expired/rejected/degraded are separate from catalog approval. Expiry must be future and at most7 days from server approval; fetched/publication times cannot be future and publication cannot follow fetch. No active catalog means scanner findings are forbidden, not automatically trusted.

## Credentials and lease ordering

Dedicated256-bit opaque runner and ingest secrets; only their SHA256 hashes persist. Prefix/audience are unambiguous, exclusively routed: POST `/api/bumblebee/lease` accepts runner only, POST `/api/bumblebee/ingest` accepts ingest only. Browser/MCP/device/memory routes reject both. Credentials are delivered by a scoped enrollment/lease response, never log/query/argv. Production transport HTTPS only; forwarded scheme trusted only from explicitly configured proxy, not arbitrary headers. Test exception limited to explicitly owned loopback fixture. No source IDs or scope in credential caller payload can override server binding.

Lease request exact `{sourceRevision:positive safe integer,operationKey:1–128 ASCII identifier}`. Under source/head/credential/owner-authority locks, require matching current revision; increment per-source monotonic generation bounded by JS safe integer, bind source/endpoint/population/profile/ecosystems/catalog revision+digest and expire in600 seconds. Operation key uniqueness is scoped to runner credential; exact replay returns same lease identity and response, changed request conflicts. Derive ingest secret as base64url HMAC-SHA256 under a dedicated server256-bit lease key over canonical JSON `["bumblebee-ingest-v1",groupId,workspaceId,sourceId,leaseId]`; store only its SHA256 plus nonsecret key revision. Replay derives identical secret, checks its hash and returns it only to the same currently authorized runner, before expiry. Missing/rotated key yields unavailable, never a replacement lease/token. No plaintext secret in audit/DB/logs; lease key cannot be cursor/JWT/redaction key. Source change/disable/owner removal/catalog invalidation denies use even before lease expiry.

## Receiver and sanitization

Authenticate/recheck exclusive credential/current authority before body read or decompression. Initial transport rejects non-identity Content-Encoding (gzip is not enabled), bounds body4MiB, each NDJSON line64KiB, records2048, concurrent work via existing budget, elapsed deadline. One upload contains one run and one final summary. Require schema0.1.0, verified scanner0.1.2 artifact origin at runner, matching endpoint/device/profile, valid128-bit hex run ID, exact record shape/types and recomputed upstream record IDs before redaction. Reject duplicate/conflicting IDs, unsupported enum, malformed/extra authority fields, missing/following-summary records, inconsistent counts and multi-run mixing. Upstream ID hashes are unkeyed dedupe, not signatures; source credentials plus lease provide authority.

Keep raw wire only within bounded request memory; never persist or log it. Validate canonical IDs then retain safe projected fields and scoped HMAC fingerprints for source_file/project_path/root/endpoint identifiers using dedicated server secret. No hostname/username/uid, raw roots, lifecycle script text, catalog text/evidence strings, environment/credential values or URL user-info in records/events/receipts/errors. Package names/versions strictly grammar/length bounded; redact all other free text. Persist original wire digest only as a scoped keyed digest so private low-entropy content is not globally correlatable. Retain redaction policy/revision and safe upstream ID fingerprint, not unqualified payload. Raw failures return fixed error codes, no exception/body echo.

## PostgreSQL transaction contract for10.2

New scope-qualified families (exact DDL owned by10.2): source heads+immutable source revisions; immutable approved catalog revisions+entries; separate runner credentials; immutable leases+mutable use/revocation state; immutable sanitized batches+records; immutable run decisions; per-source/population current head; deduplicated alerts+simulated proposal records. Every PK/unique/FK includes group_id/workspace_id, with source/revision/catalog/lease/run identities as applicable. Existing tenant/workspace/principal FKs and FORCE RLS/non-owner policies apply; no bare UUID FK can link foreign evidence. Credentials never enter ordinary current-memory search.

One scoped transaction authenticates/locks source, current owner authority, lease/catalog and current inventory head, then writes sanitized batch/records/run decision/audit receipt plus optional current pointer/alert/simulation. Faults roll back all writes. Unique lease/body keyed digest supports exact replay; same lease with changed payload conflicts. Late generation remains accepted evidence only, not current. Expired/revoked leases deny even replay before disclosure; lost response is unknown until exact reconciliation. Source/catalog changes cannot race the final eligibility check. Store schema fixtures only in explicitly owned disposable DB.

Promote routine inventory only after matching complete summary, exact root population and profile, matching emitted/received package/finding counts, zero suppressed records, zero diagnostics, no timeout, strictly newer server generation. Empty complete removes prior entries only in that same population. Partial/error/missing-summary/filtered/deep/findings-only/foreign/late runs cannot retire it. Clock skew is an observation, never ordering authority. Stale after24 hours without a valid complete run is stale, never clean. Append-only evidence retained; no automatic deletion/expiry of evidence. Credential/lease expiry removes authority, not history.

Trusted exposure is recomputed by exact ecosystem/name/version join from accepted package evidence to the lease-bound unexpired approved catalog entries. Upstream findings alone never create trusted exposure. Deduplicate alerts by scoped source/population/catalog-entry/package identity; append observations rather than deleting accepted alerts. Simulated mitigation has fixed advisory text and references only, no runnable command/activation field and no canonical semantic write. Any subsequent semantic proposal goes through existing pending proposal service and a DIFFERENT entitled human decision. Enforcement is absent.
