## Claim / cancellation / reconciliation
Explicit source/transfer owner and current authority are revalidated on every claim/outbound/read/finish. Claim due rows only, attempts<5, lease expired, no terminal state; exclusive locked row increments monotonic fence and attempt, lease30000ms. Defaults5/10/20/40/80-second backoff, actual valid Retry-After may extend due time, never shorten it; malformed or unbounded Retry-After causes conservative unknown/manual reconciliation. No sleeping inside a transaction. Every claim first reads destination. Matching content produces synced; conflicting destination/parent/source/binding/content is failed/conflict without write. Both reserved properties empty permit at most one write only if durable write_started is false and state was never unknown.

Before PATCH, separately COMMIT write_started=true and unknown observation under current claim. Lost/ambiguous commit prevents PATCH until read reconciliation; never assume a failed response means commit failed. After this marker all later claims are read-only reconciliation, even if read-back is empty (absence does not prove an in-flight remote write cannot finish). Crash before actual PATCH may therefore require a human disposition; safety wins over blind retry. No claim/failure callback clears write_started. A fresh separate authenticated bounded GET after PATCH alone can establish synced. PATCH status/page ID/local event cannot. Revoked/expired/locked source forbids new reads/writes; retain last observation evidence, report authority denial not “still current synced”. Work already admitted under a lock may complete before revocation commits; no new work after it.

Finite per-request2000ms deadline,131072byte response cap, no redirects, no ambient cookies/proxy credentials; per-process bounded work with cancellation retaining occupancy until settlement. Requests only exact configured origin/page path. Unknown after cap remains unknown with exhausted flag, not failed/synced. Stale fence/lease cannot append completion or downgrade terminal synced. No cleanup transaction after a failed transaction that may have committed. A late old worker cannot reopen delivered work. Read-only matching verification may be explicitly requested after exhaustion without authorizing another write; define this separately in7.3 if needed.
