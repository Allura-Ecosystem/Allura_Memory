## Authority / immutable base
PostgreSQL is the only durable memory authority. Branches are process-local hypothetical views, never Git branches, accepted knowledge, semantic versions or a second authoritative service. No AgenticOW/AgentDB/SONA implementation/dependency copied/executed/adopted. Future upstream execution needs explicit approval, immutable provenance/license/dependency assessment before execution.

BaseSnapshot has exactly schema=memory-experiment-base-v1, snapshotId, scope={groupId,workspaceId}, records. Each ExperimentRecord repeats scope and contains memoryId,knowledgeId,version,content,evidenceIds. UUIDs must use existing validScope syntax plus lowercase exact spelling; never normalize invalid source tokens. Version is a positive decimal string below2147483647; reject leading zeros/floats. One immutable version per knowledge identity; reject repeated memory/knowledge/evidence IDs, blank/NUL/malformed-surrogate/oversized text, unknown fields/prototypes/accessors, sparse arrays. Preserve exact content; copy/freeze nested arrays/objects. Sort records by memoryId and evidence IDs before SHA256 over UTF8 JSON. Snapshot schema,identity,scope and all fields are bound; digest is integrity, not identity, permission or signature. No raw event payloads,vectors,files,unrestricted graph/provenance.

Only server-owned readSnapshot(identity,scope,snapshotId) may supply currently visible semantics/linked evidence under restricted PostgreSQL/current authority. Client rows/digests/namespace names do not grant access. Base identity is stable even when canonical heads advance; immutable source reread and CURRENT head locks at eventual proposal/decision are separate requirements.11.1 parser does not implement this reader.

## Identity / lifetime / threat model
Every operation re-resolves branded authenticated Identity/current memory:read; creation/edit/fork/checkpoint/rollback/quarantine/dispose/candidate/verification additionally require proposal:write. No new grants; machine ceilings unchanged. Owner from resolved principal, not body. Host generates branch/checkpoint UUIDs. Branch descriptor binds ownerId,scope,snapshotId,baseDigest,parentBranchId,revision,createdAt,expiresAt,state. Owner-only, no RAM/Durham role inheritance/cross-tenant IDs. Recheck authority/principal after awaits and before disclosure/mutation. Trusted server-owned adapters cannot be caller supplied.

One in-flight operation per engine; reject busy rather than queue. One bounded authenticated workflow per engine, not a global cross-tenant pool. This is not an OS/hostile-JavaScript sandbox or measured constant-time API. Compromised adapters, event-loop starvation and already disclosed objects cannot be contained/recalled. Before real use require trusted adapter cancellation/timeouts, bounded host admission/process supervision and current authorization. Host construction is not permission to reset user-wide quotas.

Engineering ceilings:8 lifetime branch allocations;128 records/131072 UTF8 JSON bytes per base and overlay;12000 content bytes and1–31 evidence IDs/record;4 checkpoints/branch;128 successful normal operations/branch plus final dispose/quarantine. Positive integer ttl required <=3600000ms;900000ms recommended, not silently defaulted. Child expiry cannot exceed parent/engine deadline; engine maximum lifetime3600000ms. IDs/replay history remain bounded until destroy; terminal cleanup does not reset quotas.

Intended11.2 retention: unref'ed local expiry timers plus access checks; expiry/quarantine/dispose clear owned base/overlay/checkpoints/candidate references, no revival. Engine destroy permanently clears all registries/timers. Logical reference release is not secure erasure; stalled trusted adapters may retain transient refs. No persistence/import/restart path or recurring supervisor. Production-wide retention/admission remains separate.

## Lifecycle / useful export
No route is registered by the parser. Intended bounded engine methods: create/view/execute/candidate/verifyCandidate/destroy. view labels records experimentOnly:true and baseVersion; omit canonical version. put replaces content only for existing base memory IDs; tombstone hides locally, never deletes canonical memory. checkpoint copies overlay; rollback restores that branch's overlay without rewinding revision/evidence/keys. fork copies overlay/shared frozen base into a new identity with bounded expiry; no inherited checkpoint/key authority. dispose affects that branch; quarantine affects descendants even through disposed intermediates. Source drift quarantines descendants. No unquarantine or import.

Every successful write spends its operation key and increments monotonic revision. Reuse/stale revision conflicts, including after rollback/dispose; no canonical receipt semantics are changed. Sanitized invalid/not_found/conflict/quota/expired/quarantined/disposed/busy/unavailable errors plus existing authority categories; no foreign payload echoed.

Only export is ProposalCandidate, not durable Proposal or approved receipt: exact schema=memory-experiment-proposal-v1,status=requires_curator_review,canonicalMutation=false,branchId,scope,producerId,snapshotId,baseDigest,revision,expiresAt,changes,evidenceIds,rationale,candidateDigest. Select1–16 changed memory IDs/<=31 distinct evidence IDs/rationale<=4000bytes. Changes bind memoryId,knowledgeId,expectedBaseVersion,kind=replace|tombstone,before,after,evidenceIds. Sorted-key JSON body digest excludes candidateDigest; finite depth8/nodes16384/arrays128/objects32keys/serialized400000bytes. Issued engine-retained candidate, current revision/authority/source/expiry must match; recomputed client digest or cross-engine packet is not authorization. Any later successful operation invalidates prior export.

Engine has no SQL/canonical mutation/approve/merge callback.11.3 must verify issued packet then transactionally create a pending proposal under existing exact-scope/current-head/evidence/operation-key/audit rules. Independently authenticated authorized curator must differ from requester/producer/evidence actors. Rejection/rollback never changes canonical semantics. Crash/lost-ack handling must use existing durable exact receipt reconciliation, not ephemeral replay denial. Client-visible uncertain outcome is never success or inferred no-write.
