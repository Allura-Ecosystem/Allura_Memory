# Allura memory consumer — private prerelease 0.1.0-dev.1

Owner: Brooks. Contract: allura-consumer-v1, dated2026-10-27. Local rebuild, not published/deployed and not backward-compatible with the separately configured legacy tunnel. Pack receipt records exact source HEAD/input SHA256 and tarball SHA256; a HEAD without dirty-input digests is insufficient evidence. Runtime pins: Bun1.3.14, Node24.19.0; official MCP SDK1.32.2. Do not substitute a subscription/agent persona for authenticated machine authority.

## Storage and first use

All SDK/CLI/stdio writes use authenticated MCP memory_add at your explicitly configured /mcp endpoint. There is NO generic REST capture route. PostgreSQL stores append-only evidence/replay/receipts; capture is not semantic approval, scoring, or a generated proposal. Independent authorized human promotion remains required. Indexing is separately observable. External projection is not configured. Get/list default to current semantic versions; `get({kind:'receipt',id:receipt_id})` reads your exact capture receipt. These identifiers are not interchangeable. Search `status:'all'` explicitly includes eligible unapproved evidence, never other workspaces. Threshold is only an accepted future proposal-selection hint, never approval.

SDK: import {AlluraClient} from '@allura/memory-consumer'; construct with endpoint,groupId,workspaceId and an async token callback supplied by your secret manager. await client.connect(), then add/search/get/list/delete, finally close(). Inputs are typed; result data is a versioned record with server contract enforcement. invoke() retains the full MCP content/structured result for exact receipt bytes. No provider credential discovery, DevAuth or database access in this package.

CLI: allura-memory memory_add < request.json (likewise memory_search/get/list/delete). Request example: {"content":"An observed deployment fact","idempotency_key":"capture-unique-stable-key"}. Supply ALLURA_ENDPOINT (HTTPS URL ending /mcp with no query/credentials), ALLURA_GROUP_ID, ALLURA_WORKSPACE_ID, ALLURA_TOKEN through your approved environment/secret-injection mechanism, never command arguments. No default endpoint, production credential lookup or silent localhost fallback. ALLURA_ALLOW_LOOPBACK=1 permits only127.0.0.1/[::1] for an explicitly owned fixture. stdout is result JSON; disclosure/errors go to stderr. --help needs no credentials.

MCP stdio: configure the installed allura-memory-mcp executable with the same environment. It proxies the same five tools through official MCP transport; it cannot approve semantic memory or grant access. No runtime agent configuration is changed by installation. Human approval uses the separately authenticated same-origin server review API, not machine tools.

## Persistent Linux device SDK

Import `PersistentDevice` from `@allura/memory-consumer/device`. This is a Node/Bun SDK, not a browser credential store, a desktop shell or an installed agent configuration. Supported/tested platform: Linux Secret Service with libsecret `secret-tool`, GNOME Keyring, local Unix D-Bus and util-linux `flock`; binaries are `/usr/bin/secret-tool`, `/usr/bin/flock`, `/usr/bin/cat`. A logged-in local session must supply its own `DBUS_SESSION_BUS_ADDRESS` and owner-only `XDG_RUNTIME_DIR`. Missing/locked stores fail closed. No macOS/Windows support, no vault discovery and no plaintext fallback. A host running only the core server does not need these client dependencies. CI creates a private bus/keyring with synthetic keys, not a user's existing vault.

Construct with `{endpoint,groupId,workspaceId,profileId}`. The endpoint is a canonical HTTPS URL ending `/mcp`; profileId is an explicit stable local UUID, not a server role. Endpoint/tenant/workspace/profile form distinct secure-store namespaces. Keep different human accounts in different local profiles. Local fixtures alone may opt into `allowLoopback:true` for127.0.0.1/[::1] and a separately configured HTTPS `humanOrigin`; production humanOrigin must match the endpoint origin. Never use a device token as a human assertion.

1. `await device.begin(label,['memory:read','memory:capture'],humanAssertion)` persists random verifier/token and the operation key securely BEFORE requesting enrollment. Returns only public enrollment metadata. Acquire the current signed Cloudflare human session through the authorized host login flow; this package does not acquire/store it or modify grants.
2. A currently authorized human workspace administrator approves that exact enrollment through POST `/api/devices/command`, kind approve, enrollmentId, expectedRevision1 and the explicit requested action subset. The browser settings surface is separate work. Enrollment approval does not authorize semantic promotion.
3. `await device.resume(humanAssertion)` completes the approved proof exchange and stores active metadata/token. Resume also reconciles any pending begin/rotate/revoke using the identical pre-stored request after unknown outcomes; never generate a replacement request/key blindly. There is no automatic retry loop.
4. `const client=await device.connect()` returns the existing governed AlluraClient; use add/search/get/list, then close(). A new process with the same local profile reads the actual secure store. Current401/403 or authorization-denied tool results terminate this session; restoration requires a new explicit connect, not a retry inside the denied session. Every request obtains current stored state and the server rechecks authority. Pending rotation cannot use the old cached token.
5. `await device.rotate(humanAssertion)` pre-stores a replacement, then atomically rotates server authority. `await device.revoke(humanAssertion)` first stops local use, then revokes remotely and removes the local record only after a matching receipt. Unknown results retain pending state. `secure_store_busy` means another local mutation owns this exact profile; do not clear its record or launch an automatic retry.

Expired/abandoned enrollment needs a new explicit profile/enrollment and current human authentication; it is not refreshed through a device bearer. Ask an authorized administrator to revoke any abandoned outstanding device first. There is deliberately no automatic credential-reset or local-forget operation that could be mistaken for remote revocation. The kernel mutation lock survives arbitrary callback duration and releases on process death; its owner-only zero-content file is coordination metadata, not a credential. Concurrent MCP reads remain lock-free against atomic Secret Service item replacement; server generation checks reject a racing obsolete token.

Credentials/proofs travel through bounded child stdin or HTTPS bodies, never argv, URLs, result JSON or local plaintext files. Human assertions stay ephemeral. OS-user compromise or an unlocked keyring accessible to another process of the same OS user is outside this storage boundary; profile namespaces are not OS-user isolation. Test witnesses include encrypted keyring bytes, separate installed Node processes, lost responses after actual server commits, real foreign-scope/current-authority denials and client-process death. Local platform evidence is not a deployed or real-human onboarding witness.

## General error and migration contract

Never automatically retry writes or generate a new key after an ambiguous response. Timeout/disconnect may mean unknown, not rollback: repeat explicitly with the original key and unchanged payload to reconcile. Soft deletion requires exact expectedHeadRevision, reason, operationKey and current memory:delete; it does not erase history. The accepted database contract restricts workspace_admin (and therefore memory:delete) to humans: SDK/CLI/stdio machine deletion is denied, even if the credential ceiling includes that action. The same five-tool implementation is also exposed at /mcp/human for signed, current human identities with mandatory same-origin mutation protection; only a currently authorized human administrator may delete there. This is not bearer-token impersonation or a grant-policy change. Capture remains machine-only and cannot be performed with a human assertion. Human approval remains a separate review route, never a five-tool capability. Current credentials and grants are reread by the server. Initialize/read require memory:read; capture additionally memory:capture, deletion additionally memory:delete.

Request65,536 bytes/response131,072 bytes; client fetch admission16 shared in-process slots retained through actual settlement, default6s deadline (20ms–10s configurable), no redirect following or automatic reconnect/retry. CLI input60,000 bytes/6s; stdio line65,536 bytes/16 calls. This is cooperative cancellation, not forced native preemption. Server budgets remain independently enforced. Network/transport arbitrary errors are redacted, never echoed as credential-bearing text.

Legacy user_id/include_global/offset/sort contracts are NOT silently supported. This fresh package has explicit workspace binding, mandatory capture keys, signed cursors/max20 list pages and exact deletion revisions. Do not point a legacy consumer at this interface or reconfigure the live public tunnel without a separate compatibility migration. No Neo4j dependency. Packed local tests are not clean hosted initialization, independent human usefulness, production load, browser/interactive graph, backup/recovery or release acceptance.
