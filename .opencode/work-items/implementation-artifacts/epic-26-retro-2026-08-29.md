## Findings

### F1 — Self-review honesty: the first AC-18 "9/9 complete" claim was false (process lesson)
The first freeze claimed a complete headless matrix on 9 cases. Independent AC-19 review (Pike/Fowler/Knuth) correctly rejected it: partial/error/missing-summary statuses, filtered/changed population, stale/future clock, gzip-limit, and DB-failure paths were genuinely uncovered. **Accepted as a process lesson:** an acceptance gate must be independent of the implementer's self-claim, and "covered" means live-observed, not "looks covered." Reopened and honestly re-proven with 15 live cases across two e2e suites. Sources: `bumblebee-headless-ingest.e2e.test.ts` (10 cases), `bumblebee-headless-matrix2.e2e.test.ts` (4 cases + DB-failure documented unit-proven).

### F2 — Records-grain inversion was real and spec-level; Correct Course was the right tool (accepted)
`bumblebee_records` PK originally omitted `source_revision_id`/`lease_id`/`batch_id` and let scanner-supplied `run_id` lead uniqueness — a promoted decision could cite a summary from another lease/generation. The AC-19 reviewers identified it from the schema; migration 52 corrected the grain and the live negative test proved cross-lease citations now fail at the FK. **Lesson:** read the tables before trusting the process — one `awk` over primary keys exposed in seconds what the full loop had not.

### F3 — CI coverage had silently drifted (deferred, tracked)
The ac19 remediation merge (`eda0655d`) dropped `bumblebee-headless-ingest` from `vitest.config.live-db.ts`, so the claimed live-DB totals on that branch never ran the headless matrix. Caught during closure; include restored and matrix2 added. **Lesson:** a live-DB lane's include list is load-bearing; verify config diffs in review like code diffs.

### F4 — Gzip/encoding limit was incidental, not deliberate (fixed)
AC-7 requires unsupported encodings to fail closed. The pipeline rejected gzip bytes incidentally as `400 MALFORMED_LINE`. Fixed with an explicit content-encoding gate (`415 BUMBLEBEE_BATCH_UNSUPPORTED_ENCODING`) before body read; +3 unit tests. Source: `src/lib/bumblebee/ingest-pipeline.ts` (2b gate).

### F5 — FK auto-naming assumption was wrong and would have bricked migrate-only (accepted)
The brief assumed `bumblebee_run_decisions_summary_record_id_fkey`; PG auto-names inline FKs to 63 chars (`..._source_id_ru_fkey`). Verified live before writing migration 52 — a wrong drop would have failed the whole migrate-only lane. **Lesson:** verify auto-generated constraint names against a live apply, never assume.
